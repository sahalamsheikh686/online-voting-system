ONLINE VOTING SYSTEM - ALGORITHMS, LOGIC, SECURITY, AND FILE REFERENCES
========================================================================

Project Type:
Laravel based Online Voting System.

Main Purpose:
This project manages voter registration, admin approval, election-wise candidate
management, secure login, election start/pause/resume/end flow, vote casting,
winner calculation, reports, and election archive/restore.

Important Note:
This project does not use advanced cryptographic voting algorithms like
blockchain, RSA vote encryption, homomorphic encryption, biometric verification,
or OTP. It uses practical application-level algorithms and Laravel security
features such as hashing, middleware, CSRF protection, validation, transactions,
database constraints, and role based access control.

21. TURNOUT / PARTICIPATION CALCULATION ALGORITHM
=================================================

Used Logic:
- Each approved voter can cast two votes: President and Vice President.
- Total possible votes = approved voters * 2.
- Turnout percentage = votes cast / total possible votes * 100.
- If approved voters are 0, turnout is 0 to avoid division by zero.

File References:
- app/Http/Controllers/Reports/ReportController.php

Formula:
- turnout = round((votesCast / max(approvedVoters * 2, 1)) * 100, 2)

28. VIVA / REPORT PRESENTATION SUMMARY
======================================

You can explain the algorithms like this:

This Online Voting System uses application-level algorithms for secure voting
workflow. The authentication algorithm verifies contact number and password.
The authorization algorithm separates admin and voter
access using middleware. The voting algorithm validates election status,
candidate election, candidate position, and duplicate voting before storing
votes inside a database transaction. The winner calculation algorithm counts
votes position-wise and detects tie cases. The election lifecycle algorithm
handles start, pause, resume, end, archive, and restore operations. The reporting
algorithm aggregates election-wise votes, candidate votes, turnout percentage,
voter status, and election summary into PDF or Excel reports.


29. PROJECT WEIGHT POINTS FOR BCA FINAL YEAR
============================================

Strong Features:
- Laravel full-stack project.
- Admin and voter role based access.
- Voter registration with admin approval.
- Contact number and password authentication.
- Election-wise voting.
- One person, one ballot logic.
- President and Vice President position-wise voting.
- Election start, pause, resume, and end lifecycle.
- Winner and tie calculation.
- Dashboard charts.
- PDF/Excel reports.
- Election archive and restore.
- Database constraints and relationships.
- Validation and middleware security.

Limitations:
- Vote is not fully anonymous because votes are linked with user_id.
- No OTP/email verification in current implementation.
- No blockchain or advanced cryptographic vote encryption.
- Audit logging is currently limited mainly to report export.

Recommended Claim:
This is a secure academic online voting management system with authentication,
role-based access, election-wise voting, vote validation, result calculation,
election lifecycle management, reporting, and archive/restore features.
